## Coverage reality

Only `partner_custom_fields` ships tests (`tests/test_field_translate.py`):
label / type / selection translatability, `translate` → `ir.model.fields.translate`,
HTML vs standard, integer ignored, copied translations, form arch after a
translated label. It activates `fr_FR` itself.

The other seven modules have no `tests/` package. `Gx.2` / `Gx.7` prove
install + upgrade + those translate tests, not the product claims. The rest are
named manual checks on the `Gx.8` review database.

## Port-relevant surface

- **ACL**: every module ships `security/ir.model.access.csv` (two website files
  are header-only). No `ir.rule`. `Gx.3` → `ir.access.csv`.
- **Views**: `opportunity_custom_fields` inherits `crm.crm_lead_view_form`.
  At saas-19.4: `group name="lead_priority"` is gone (`tag_ids` before remains);
  `page name="lead"` is gone (Extra Info `page extra` is the surviving tab and
  is not type-gated); the first `//sheet/group` is a mobile-only revenue block,
  so the two-column hook is `//sheet/group[group[@name='lead_partner']]`.
  The checker missed `page lead` because that name exists elsewhere (global
  name lookup). Demo placements (`left_panel_group` / `right_panel_group` /
  `group_custom_fields`) still match the surviving hooks.
- **JS/OWL**: none (`useState` / `t-ref` / `get_param` absent).
- **Layer-1 demo**: field/type XML in the document modules. `custom_fields` and
  the two website modules ship no Layer-1 records of their own.
- **Layer-2**: `odootools_demo.models.demo_custom_fields` stamps values onto
  generated `x_oz_*` columns. Review only — do not edit `system` 19.0.
